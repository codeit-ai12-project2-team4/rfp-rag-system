# 골든셋 규격 (generation 팀 전달용)

한 세트로 **검색 채점과 E2E 채점을 둘 다** 한다. 분기는 세트 형식이 아니라
`doc_id` 가 우리 코퍼스에 있느냐로 갈린다.

    doc_id 가 우리 코퍼스에 있다   → 검색 + 생성 (E2E). 이게 기본이다
    없다 (합성 문서 등)            → 생성만. evidence_text 로 발췌를 짓는다
                                    scripts/retrieval/contexts_from_evidence.py

## 한 줄의 모양

```json
{
  "question": "제안서 평가비율 중 가격평가의 점수는 얼마인가?",
  "doc_id": "20240330003-0",
  "keywords": ["제안서 평가비율 : 기술평가(90%), 가격평가(10%)"],
  "type": "배점",
  "answerable": true,
  "evidence_text": "…",
  "answer": "가격평가는 10%다"
}
```

| 키 | 필수 | 무엇 |
|---|---|---|
| `question` | O | 질문 한 문장 |
| `doc_id` | O | **우리 코퍼스의 id.** `공고번호-차수`(`20240330003-0`) 또는 `data/raw` 의 파일명. 파일명이면 우리가 바꾼다 |
| `keywords` | O | 채점용 정답. **문서 본문에 글자 그대로 있는** 짧은 조각. 리스트 |
| `type` | O | `배점` · `요구사항` · `의역` · `없음` |
| `answerable` | O | `없음` 유형은 **반드시 false** |
| `evidence_text` | △ | 근거 원문. 검색 없이 생성만 잴 때 쓴다 |
| `answer` | △ | 사람이 볼 정답. **채점에는 안 쓴다** |

`answer` 를 안 쓰는 이유: 정답포함 지표는 폐기했다(9/8). gold 가 문장이라
모델이 바꿔 쓰면 무조건 0 이 되어 답변 품질이 아니라 지표의 결함을 잰다.

## 다섯 가지만 지켜 주면 된다

**1. `doc_id` 는 우리 코퍼스 것으로.**
`[SYNTHETIC] 누리테크_…` 같은 건 E2E 를 못 잰다. 발췌가 통째로 비어서
전부 0점이 나오고, 그건 성능이 아니라 입력이 빈 것이다(2026-09-03 실제 사고).

**2. `keywords` 는 본문에 글자 그대로 있어야 한다.**
근거를 통째로 붙이면 안 된다. 여러 곳을 이어 붙였거나 쪽번호·표 찌꺼기가 섞이면
**글자 그대로는 코퍼스에 38~53% 밖에 없다.** 그러면 검색이 아무리 좋아도
적중률이 0.5 에서 막힌다. 근거와 본문의 **가장 긴 연속 일치 조각**을 쓸 것.

**3. `answerable: false` 문항을 꼭 넣어 달라.** 전체의 10~15%.
생성에서 제일 중요한 건 **근거가 없을 때 없다고 말하는가** 다. 지금 쓰는
`eval_qa_both` 는 전부 `answerable: true` 라 그걸 못 잰다. 답할 수 없는 문항이
하나도 없으면 물러섬 지표가 의미를 잃는다.

**4. 질문이 공고를 특정하게.** 1단계(공고 검색)를 재려면 문장만 보고 어느
공고인지 알 수 있어야 한다. "가격 평가 배점이 몇 점인가" 는 거의 모든 공고에
있어서 검색 성능이 아니라 운을 잰다. 사업명이나 발주기관을 넣어 달라.

**5. 표에서 정규식으로 뽑은 문항은 사람이 한 번 보고 넘겨 달라.**
지금 세트에 이런 게 섞여 있다.

    "C 업체의 하도급계획 적정성 평가에서 '0점 (서류 미제출)'를 받았다면 그 이유는?"
      → RFP 에는 평가표 **양식**만 있고 C 업체는 없다. 답할 수 없는 질문인데
        answerable: true 로 되어 있어, 모델이 옳게 물러서도 오답으로 센다

    "A 업체의 신용평가등급이 BBB-, BB+, BB 중 어느 등급인가"
      keywords: ["0점 0 (서류 미제출) <인증유형>"]
      → 질문과 정답이 아예 다르다

이런 문항이 많으면 충실성·물러섬이 낮게 나오는데 **그건 모델 성능이 아니다.**

## 우리가 재는 지표

    인용표시율   답변에 [n] 을 달았나
    인용정확도   그 [n] 이 발췌 번호 범위 안인가
    숫자근거율   답변의 숫자가 발췌 안에 있는가
    충실성       발췌에 있는 내용만 말했나 (LLM 채점)
    물러섬       근거가 없을 때 모른다고 했나 ← answerable: false 가 있어야 뜻이 있다

Groundedness 는 안 잰다 — 충실성과 사실상 같은 것을 묻는데 LLM 호출만 두 배다.

## 넘겨 받은 뒤 우리가 하는 것

```bash
# 0) 세트가 쓸 만한지 (문항 수·유형 분포·코퍼스 매칭)
python scripts/retrieval/adapt_evalset.py --src <세트> --docs cleaned_documents

# 1) 5문항 연습 → 2) 본 실행 → 3) 채점
#    자세한 건 scripts/README.MD

# 점수가 낮으면 세트 탓인지 모델 탓인지 먼저 가른다
python scripts/retrieval/score_answers.py <answers.jsonl> --misses
```
