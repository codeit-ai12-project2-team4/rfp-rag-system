# 입찰메이트 크론.  설치:  crontab docker/crontab.txt
#                   확인:  crontab -l
#                   로그:  tail -f /tmp/index.log
#
# 절대경로로 쓴다 — 크론은 PATH 도 가상환경도 물려받지 않는다. `python` 이라고
# 쓰면 시스템 파이썬이 잡혀서 "ModuleNotFoundError: lancedb" 로 조용히 실패한다.
#
# 세 단계(수집 → 전처리·색인 → 반영)는 docker/refresh.sh 안에 있다.
# 여기 다섯 줄에 같은 명령을 복붙하면 나중에 한 군데만 고치게 된다.

SHELL=/bin/bash
HOME=/home/spai1203

# --- 낮: 3시간마다 받고 그 자리에서 반영한다 --------------------------------
#
# 4시간을 되돌아봐서 **일부러 겹치게** 한다. 겹쳐도 이미 가진 doc_id 는
# 건너뛰므로 마지막 실행 시각을 적어둘 상태 파일이 필요 없다. 상태 파일은
# 크론이 한 번 실패하면 그 구간이 영영 구멍으로 남는다.
#
# **9/9 부터 낮에도 반영한다.** 전에는 받기만 하고 색인은 새벽에 한 번이라,
# 낮에 올라온 공고가 다음 날까지 검색에 안 나왔다. 막던 건 재시작 2분 반이었고,
# 그 정체는 BM25 형태소 분석이었다. 캐시하고 나서 기동이 1.9초가 됐다.
0 12,15,18,21,0 * * * $HOME/rfp-rag-system/docker/refresh.sh --hours 4 >> /tmp/index.log 2>&1

# --- 새벽: 이틀치를 다시 훑는다 --------------------------------------------
#
# 낮에 놓친 것(공고 수정·지연 등록)을 메운다.
30 3 * * * $HOME/rfp-rag-system/docker/refresh.sh --days 2 >> /tmp/index.log 2>&1

# 로그가 무한정 자라지 않게. 일요일 새벽에 자른다.
0 4 * * 0 : > /tmp/index.log


# --- 알아 둘 것 -------------------------------------------------------------
#
# **한 번에 하나만 돈다.** refresh.sh 가 flock 을 잡는다. 앞 실행이 아직이면
# 조용히 건너뛴다 — 겹쳐 돌면 같은 청크를 두 번 임베딩하고, /reload 가 반쯤
# 만든 색인을 집어 간다.
#
# **증분이다.** 전처리는 지난번 결과를 캐시로 써서 새로 들어온 파일만 다시
# 뽑고, 색인은 lance 테이블에 새·바뀐 공고만 넣는다. BM25 는 형태소 분석
# 결과를 본문 해시로 캐시한다. 그래서 드는 시간은 코퍼스 크기가 아니라
# **그 사이에 들어온 양**에 비례한다. 새 공고가 없으면 몇 초에 끝난다.
# 전처리 코드를 고쳤으면 캐시가 저절로 무효가 된다(모듈 mtime 을 본다).
#
# **왜 재시작이 아니라 /reload 인가.** API 가 인덱스를 lru_cache 로 물고 있어
# 새로 만들어도 그냥은 새 공고를 못 본다. /reload 는 새 청크로 BM25 를
# **먼저 짓고 그 다음에** 캐시를 비운다. 도는 동안 들어온 요청은 옛 인덱스로
# 정상 응답한다. sudo 도 필요 없다.
#   실패하면 /tmp/index.log 에 남는다. 그때는 손으로:
#     sudo systemctl restart bidmate-api
#
# **청크 파일 이름(CHUNKS)을 바꿨을 때만** 재시작이 필요하다. import 때 읽은
# 값을 쓰기 때문이다. 코퍼스 버전을 올릴 때 말고는 그럴 일이 없다.
#
# **STORE=lance 는 .env 에 있으므로 여기 안 적는다.** 두 군데 적으면 한쪽만
# 고치게 된다. prepare.py 가 .env 를 읽어 lance 쪽만 검사·생성한다.
#
# **낮에 도는 것의 전제 — 8B 모델을 안 올린다.** 받아서 파싱하고 임베딩하는
# 스파이크가 1~3GB 인데, 8B 가 올라간 상태에서 질문이 겹치면 OOM 킬러가 제일
# 큰 프로세스를 고른다. 8B 를 되살리면 낮 반영을 새벽으로 되돌릴 것.
