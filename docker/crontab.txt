# 입찰메이트 수집 크론.  설치:  crontab docker/crontab.txt
#                       확인:  crontab -l
#                       로그:  tail -f /tmp/crawl.log
#
# 절대경로로 쓴다 — 크론은 PATH 도 가상환경도 물려받지 않는다. `python` 이라고
# 쓰면 시스템 파이썬이 잡혀서 "ModuleNotFoundError: lancedb" 로 조용히 실패한다.

SHELL=/bin/bash
HOME=/home/spai1203

# 업무시간에 3시간마다. 4시간을 되돌아봐서 **일부러 겹치게** 한다.
# 겹쳐도 이미 가진 doc_id 는 건너뛰므로, 마지막 실행 시각을 적어둘 상태 파일이
# 필요 없다. 상태 파일은 크론이 한 번 실패하면 그 구간이 영영 구멍으로 남는다.
0 9-18/3 * * * cd $HOME/rfp-rag-system && .venv/bin/python src/crawl.py --hours 4 >> /tmp/crawl.log 2>&1

# 새벽에 이틀치를 다시 훑는다. 낮에 놓친 것(공고 수정·지연 등록)을 메운다.
30 3 * * * cd $HOME/rfp-rag-system && .venv/bin/python src/crawl.py --days 2 >> /tmp/crawl.log 2>&1

# 로그가 무한정 자라지 않게. 일요일 새벽에 자른다.
0 4 * * 0 : > /tmp/crawl.log

# --- 수집 → 전처리 → 색인 → 재시작 -----------------------------------------
#
# 새벽 크롤링이 끝난 뒤에 돈다(3:30 시작, 45분이면 넉넉). prepare.py 가
# 전처리본·청크·인덱스·평가세트를 순서대로 보고 없는 것만 만든다.
# 새 공고가 없으면 전부 O 로 지나가고 몇 초에 끝난다.
#
# **STORE=lance 는 .env 에 있으므로 여기 안 적는다.** 두 군데 적으면 한쪽만
# 고치게 된다. prepare.py 가 .env 를 읽어 lance 쪽만 검사·생성한다.
45 3 * * * cd $HOME/rfp-rag-system && .venv/bin/python scripts/retrieval/prepare.py --build >> /tmp/index.log 2>&1 && sudo systemctl restart bidmate-api

0 4 * * 0 : > /tmp/index.log

# 재시작이 필요한 이유: API 가 인덱스를 lru_cache 로 물고 있어서, 새로 만들어도
# 재시작 전에는 새 공고를 못 본다. 기동에 2분 반 걸리지만 새벽 3시 45분이다.
#
# `sudo` 가 비밀번호를 물으면 크론이 멈춘다. 한 줄 허용해 둘 것:
#   sudo visudo -f /etc/sudoers.d/bidmate
#   spai1203 ALL=(root) NOPASSWD: /bin/systemctl restart bidmate-api
#
# **전처리는 원본 전체를 다시 읽는다.** 공고가 쌓일수록 이 줄이 길어진다.
# 증분 경로(새 문서만 처리)가 붙기 전까지는 코퍼스 크기를 지켜볼 것.
